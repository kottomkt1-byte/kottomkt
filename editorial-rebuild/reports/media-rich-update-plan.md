# Media-rich update — 검수 계획

목표는 기존 12페이지의 기능을 보존하면서 첫 화면과 본문에서 실제로 볼거리가 충분한지 확인하는 것입니다. 파일 개수나 기능 테스트만으로 시각적 완성도를 통과시키지 않습니다. 기존 production build `a849451`을 먼저 캡처하고, 최종 통합 freeze 이후 새 빌드를 검사합니다.

## 실제 화면 비교

- 전체 12페이지를 1440×900 / 390×844에서 열고 첫 화면과 중간을 캡처합니다.
- 히어로의 사진·영상·일러스트 가시 면적, 한국어 제목의 줄바꿈, 본문 길이, 시선이 머물 곳과 CTA를 직접 봅니다.
- 후속 섹션에도 업무와 관련된 사진·일러스트가 있는지, 하나의 이미지를 의미 없이 반복하거나 텍스트를 그래픽처럼 포장하는 데 그치지 않는지 봅니다.
- 이미지 크롭과 해상도, 영상 poster와 실제 재생 프레임, 텍스트 대비, 모바일 화면에서의 압축·겹침을 검사합니다.
- 원래 자료나 실제 고객 작업이 아닌 제작 이미지가 고객 사례/실제 회사 사진으로 오해되지 않는지 확인합니다.

## 이번 요청의 내용 계약

- 홈에서 홈페이지형 블로그 제작 사례 갤러리를 제거합니다. 관련 제작 사례는 홈페이지형 블로그 상세에 7개 모두 보존되어야 합니다.
- 고객 후기 15개 + 문의 대화 8개 원본 접근을 유지합니다.
- 네 가지 성과 값과 해당 라벨을 유지합니다: 안경 제작 사례 작성 5,000건+, 메인 품목 재계약률 100%, 전문성 만족도 98%, 에실로 얼티밋 전국 순위 2위.
- 12개 경로, 내비게이션, FAQ, 고객 자료 뷰어, 연락처·지도, 문의 폼의 검증과 전송 계약을 유지합니다.
- 문의 테스트에서는 SDK를 mock으로 대체하고 실제 EmailJS API 요청을 차단합니다.

## 모션·영상·접근성

- 주요 스크롤 장면의 시작/중간/끝과 역방향을 확인합니다.
- 영상은 파일 존재 여부 대신 `currentTime` 증가와 실제 프레임을 확인합니다.
- 일시정지·재생 컨트롤, 모바일 사용자 조작, 화면 밖 일시정지 정책을 확인합니다.
- `prefers-reduced-motion`과 `navigator.connection.saveData`에서 poster와 읽을 수 있는 콘텐츠가 남는지, 자동 재생·불필요한 영상 요청이 억제되는지 확인합니다.
- JavaScript 비활성화 시 필요한 정적 콘텐츠·원본 링크·내비게이션 대체 경로를 확인합니다.
- 메뉴와 이미지 대화상자의 키보드 접근·Escape·초점 복귀를 실제로 조작합니다.
- 초기·스크롤 후 CLS, 오류, 가로 넘침, 이미지 로딩을 검사하고 별도 왕복 스크롤에서 rAF 간격을 관찰합니다. 클라우드 에뮬레이션을 실기기 성능 보장으로 표현하지 않습니다.
