# Media-rich update — 실제 브라우저 QA

검수일: 2026-10-09. Chromium에서 1440×900 데스크톱과 390×844 모바일을 실제 실행했습니다. 이전 `a849451` 빌드의 12페이지를 먼저 기록한 뒤 변경된 빌드를 비교했습니다. 검수용 `127.0.0.1:4181`은 외부 미리보기 주소가 아닙니다.

## 검사 범위와 결과

| 범위 | 실제 실행 | 결과 |
|---|---:|---|
| 전체 12페이지 일반 모션 | 24개 화면 조합 | JS·콘솔·HTTP 오류 0, 문서 가로 넘침 0, 이미지 파일 디코딩 실패 0 |
| 첫 화면·중간 화면 | 48장 및 추가 장면 캡처 | 실제 픽셀 비교 완료 |
| 서비스 후속 대형 미디어 | 7개 상세 × 2폭 | 모두 표시·로딩 확인 |
| 축소 모션 | 7개 경로 × 2폭 | 첫 화면과 페이지 끝 콘텐츠·가로 넘침 검사 통과 |
| JavaScript 비활성화 | 홈·홈페이지형 블로그 × 2폭 | 원본 링크와 정적 콘텐츠 표시, 가로 넘침 없음 |
| 영상 정책 | 일반·축소 모션·Save-Data × 2폭 | 실제 재생·정지·poster·요청 정책 확인 |

축소 모션의 7개 경로는 홈, 회사 소개, 서비스 목록, 홈페이지형 블로그, 브랜드 블로그, 문의, 위치입니다. 모든 브라우저와 모든 실기기를 검수했다는 뜻은 아닙니다.

초기·관찰 CLS는 대부분 0이었고, 데스크톱 서비스 5개에서는 0.00248–0.00859였습니다. 최댓값은 홈페이지 제작의 0.00859입니다. 홈의 네이티브 왕복 스크롤 검사에서는 CLS 0이었습니다. 전체 CLS가 0이라고 보고하지 않습니다.

## 이번 변경의 보존 조건

- **홈의 홈페이지형 블로그 갤러리 제거:** 홈에서 `[data-ev-portfolio]`와 portfolio 원본 링크 모두 0개입니다.
- **홈페이지형 블로그 상세:** 제작 사례 원본 7개를 두 화면 크기에서 실제로 열고 디코딩했습니다. 가로 터치 이동·썸네일·마지막 사례·원본 확대도 확인했습니다.
- **후기와 문의:** 홈의 후기 15개, 문의 대화 8개를 두 화면 크기에서 각각 원본 뷰어로 열었습니다. 기본 보기에서는 원본 전체를 `contain`으로 보여줍니다. 확대/스크롤, 이전·다음, 좌우 키, Tab 유지, Escape와 초점 복귀가 작동합니다.
- **기존 원본:** 제작 사례 7개 + 후기 15개 + 문의 8개는 기존 저장소 파일과 SHA-256·치수 모두 동일합니다. 외부 고객에게 후기의 진위를 새로 확인한 것은 아닙니다.
- **성과:** 안경 제작 사례 작성 `5,000건+`, 메인 품목 재계약률 `100%`, 전문성 만족도 `98%`, 에실로 얼티밋 전국 순위 `2위`가 정확한 라벨과 함께 유지됩니다. 값의 표기를 검수했으며 외부 감사를 수행하지 않았습니다.
- **내비게이션:** 메뉴 열기, 모든 링크 표시, Tab/Shift+Tab 초점 유지, Escape, 닫기 후 초점 복귀, 모바일 메뉴 하단의 닫기 버튼을 실제 조작했습니다.
- **서비스 인터랙션:** 플레이스·인스타그램·카페·당근의 세 가지 선택, 홈페이지 제작의 PC/모바일 전환, 7개 서비스 FAQ를 두 화면 크기에서 실제 조작했습니다.
- **문의:** 필수값·동의·전화번호 검증, 대기 중 중복 방지, 성공 후 초기화, 실패 시 내용 유지 및 메시지 노출을 확인했습니다. SDK를 mock으로 대체하고 실제 EmailJS API를 차단했으므로 실제 문의는 보내지 않았습니다. 기존 service/template와 payload 필드 계약이 유지됩니다.

## 영상과 모션

영상 파일 존재 여부에 그치지 않고 실제 `currentTime` 증가와 디코딩된 화면을 확인했습니다. PC에서는 desktop MP4, 390px에서는 mobile MP4가 선택됩니다. 0.7초, 4.5초, 8.3초, 12.2초의 실제 프레임을 캡처해 배경 장면 변화·한국어 대비·버튼과 캡션을 확인했습니다.

| 조건 | 초기 상태 | 사용자 조작 |
|---|---|---|
| 일반 | 자동 재생, 영상 요청 1개, 시간 증가 | 일시정지 시 시간 정지, 다시 재생 시 시간 증가 |
| 축소 모션 | `src` 없음, 영상 요청 0개, poster 표시 | 명시적 재생 버튼을 누르면 영상 재생 |
| Save-Data | `src` 없음, 영상 요청 0개, poster 표시 | 명시적 재생 버튼을 누르면 영상 재생 |

세 조건을 PC·모바일에서 모두 확인했습니다. 화면 밖에서는 영상이 멈추고, 사용자가 직접 멈춘 상태는 다시 스크롤해 들어와도 유지됩니다. 제어 버튼은 두 화면에서 높이 44px이며 화면 안에 표시됩니다.

데스크톱 홈 히어로 진행률 `0 → 0.501 → 1`, 이야기 장면 `0 → 1 → 2`를 캡처했습니다. 네이티브 휠 역방향에서는 시작 상태로 복귀합니다. 모바일은 긴 pin 연출을 사용하지 않고 세 이야기 버튼으로 장면을 선택할 수 있습니다. 각 버튼의 실제 선택 상태와 이미지 로딩도 확인했습니다.

클라우드 Chromium, DPR 1에서 녹화 없이 관찰한 rAF 간격:

| 구간 | 샘플 | p95 | 최대 | 34ms 초과 |
|---|---:|---:|---:|---:|
| 데스크톱 히어로 왕복 | 394 | 16.7ms | 83.3ms | 1 |
| 데스크톱 이야기 왕복 | 356 | 16.7ms | 33.3ms | 0 |
| 모바일 히어로 스크롤 | 308 | 16.8ms | 16.8ms | 0 |
| 모바일 이야기 스크롤 | 305 | 16.8ms | 16.8ms | 0 |

브라우저 영상 통계는 데스크톱 216프레임 중 2개 드롭, 모바일 180프레임 중 0개 드롭이었습니다. 당시 다른 팀의 offline 검수가 일부 겹쳤으나 83.3ms 프레임의 원인으로 단정하지 않습니다. 드롭이 전혀 없었다거나 실기기에서도 60fps가 보장된다고 표현하지 않습니다.

## 직접 본 시각적 변화와 수정

이전 첫 화면에서 사진·영상·일러스트가 없던 8개 경로에도 이제 시각 자료가 표시됩니다. 새 12페이지 모두 두 화면 크기에서 첫 화면에 이미지 또는 영상이 들어옵니다. 서비스 상세 7개에는 별도의 대형 후속 미디어 구간이 있습니다. 실물 소재, 편집 작업대, 사진 셀렉션, 동네 일러스트와 소통 일러스트가 서로 다른 업무 설명에 사용됩니다. 회사 소개·문의·위치에도 해당 맥락의 이미지가 들어옵니다.

전체 첫 화면·중간 화면의 비교 이미지, 서비스 후속 미디어, 홈 장면 전환, 원본 뷰어, 영상의 네 장면을 직접 열어 보았습니다. 의미 없는 영문 제목이나 장식 글자가 추가되지 않았고, 제작 이미지는 브랜드 이미지/가상 일러스트로 표시됩니다. 위치 페이지의 동네 그림은 실제 지도라는 설명으로 사용되지 않습니다.

브랜드 소재는 여러 페이지에서 다시 사용합니다. 모든 페이지가 각기 다른 사진을 독점적으로 갖는 구성은 아닙니다. 텍스트를 그래픽으로 대신했던 이전 구성과 달리 사진·일러스트·영상으로 정보의 흐름을 나눴습니다. 홈의 표시 글자 수는 약 274자 감소했으나 서비스 상세는 설명과 캡션 때문에 약 96–222자 늘었습니다. 따라서 전체 문장 수를 대폭 줄였다고 보고하지 않습니다.

발견하고 해결한 사항:

1. **PC 히어로 끝에서 영상 버튼·캡션이 화면 밖으로 이동:** 전체 미디어 wrapper에 확대/이동을 적용해 생긴 문제였습니다. 변형 대상을 video 요소로 좁혔고, 같은 끝 상태를 다시 열어 두 요소가 화면 안에 있는지와 실제 일시정지가 되는지 확인했습니다. 수정 전·후 캡처와 결과는 `reports/media-rich-update-fixes.json`에 연결됩니다.
2. **모바일 홈페이지형 블로그의 첫 이미지가 너무 아래에 배치됨:** 중복된 장식 제목을 모바일에서 숨기고 프레임 높이를 조정했습니다. 통합 담당자가 1440/390에서 원본 열기·7개 사례·오류·넘침을 재검수했고, QA 담당도 수정된 두 캡처를 직접 확인했습니다. 결과는 `reports/media-rich-hpblog-refinement.json`입니다.

최종 부분 수정 후 빌드는 `main-FDtTForv.css` / `main-eJp9jETE.js`입니다. 전체 검수 결과에는 수정 전의 최초 관찰도 보존되어 있습니다. 히어로 버튼의 초기 넘침 기록은 수정 재검수 파일과 함께 읽어야 합니다. 변경된 항목만 다시 확인했으며 동일한 전체 검사를 반복 실행한 것으로 표기하지 않습니다.

기능 검사 통과를 디자인 승인이나 수상 수준의 객관적인 판정으로 간주하지 않습니다. 모바일 원본 후기의 긴 대화는 썸네일에서 모두 읽는 구성이 아니며, 큰 보기와 확대를 사용합니다. 실제 저사양 휴대폰, Safari, 느린 외부 네트워크의 체감 품질은 이번 검수 범위에 없습니다.

## 실제 화면 녹화와 재현

새 홈의 영상과 장면 선택, 성과, 서비스 연결을 따라 **홈 → 인스타그램 → 플레이스 → 회사 소개**로 실제 링크와 메뉴를 눌러 이동했습니다. 서비스 본문에서는 추가 사진/일러스트 구간을, 회사 소개에서는 새 제작 과정 구간을 보여줍니다.

- `share/recordings/kotto-media-rich-desktop.mp4`: 1440×900, 44.87초, 7.72MB.
- `share/recordings/kotto-media-rich-mobile.mp4`: 390×844, 42.60초, 2.83MB.

실제 Chromium CDP 프레임을 시간 간격대로 인코딩했습니다. 정지 사진을 이어 붙여 웹사이트가 작동한 것처럼 만들지 않았습니다. 각 영상에서 8개 시점을 추출해 직접 확인했으며, 모바일 서비스 제목의 등장 애니메이션은 추가 23초 프레임에서 끝까지 표시되는 것을 확인했습니다. 공유 사본의 SHA-256은 녹화 원본과 동일합니다.

```bash
python qa/media-audit.py --base http://127.0.0.1:4181
python qa/media-audit.py --base http://127.0.0.1:4181 --record
```
