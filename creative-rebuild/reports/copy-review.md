## 검토 범위와 결과

직접 읽은 구현 파일은 `creative-rebuild/a.html`, `b.html`, `c.html`, `src/a.js`, `src/b.js`, `src/c.js`다. HTML 본문뿐 아니라 서비스 탭에서 교체되는 JavaScript 문안도 검토했다. 이 검토에서는 홈페이지 구현 파일을 직접 변경하지 않았다.

세 콘셉트 모두 안경원 원장님·운영자가 마케팅 대행 서비스를 검토하는 흐름을 유지한다. 확인한 문안에는 가짜 고객명, 고객 후기, 성과 수치, 운영 경력, 계약 조건, 매출·순위 보장이 없다. 안경 판매나 결제를 유도하는 문구도 없다. CTA는 서비스 장면 이동, 콘셉트 비교, 공개 이메일 작성으로 연결된다.

| 콘셉트 | 적용된 헤드라인 | 핵심 의미 |
| --- | --- | --- |
| A · 몰입형 | 안경원의 전문성이 고객에게 닿도록. | 안경원의 전문성과 콘텐츠 업무 연결 |
| B · 에디토리얼 | 좋은 안경원을 제대로 알리는 일. | 전문적인 설명과 제작 과정을 읽기 쉬운 글로 정리 |
| C · 실험형 | 원장님의 설명이 콘텐츠가 됩니다. | 매장에서 나누는 설명을 채널에 맞는 콘텐츠로 편집 |

이 결과는 문안의 사실 범위·문체·동작 설명 검토다. 브라우저의 실제 줄바꿈·가독성·화면 대비·읽기 순서 및 링크 실행은 별도 시각 QA 결과와 함께 판단해야 한다. 매출·전환율 또는 사람 같은 정도를 수치로 평가하지 않았다.

## 사실 확인 기준

사용자가 지정한 고또마케팅의 안경원 전문 광고·콘텐츠 마케팅 업종과 주 독자를 기준으로 삼았다. 기존 사이트의 레이아웃이나 슬로건은 계승하지 않고, 원문 서비스 범위와 공개 연락처만 참고했다.

| 정보 | 확인 범위 | 이번 적용 |
| --- | --- | --- |
| 브랜드와 업종 | 사용자 명시 및 원문 기재 | 고또마케팅, 안경원 전문 마케팅 |
| 서비스 | 리디자인 전 서비스 원문 | 브랜드 블로그, 홈페이지형 블로그, 인스타그램, 플레이스, 홈페이지, 당근마켓, 카페 바이럴 |
| 지도 채널 | 원문 기재 | 네이버, 카카오, 구글 지도 |
| 공개 문의 주소 | 원문 기재 | `communication@kotto.kr` |
| 고객 사례와 성과 | 원자료·공개 동의 미확보 | 사용하지 않음 |
| 제작 주기·가격·응답 시간·보장 | 확인된 조건 없음 | 새로 만들지 않음 |

기존 사이트에 적혀 있다는 사실은 수치나 후기가 검증되었다는 뜻이 아니다. 재계약률 100%, 만족도 98%, 5,000건, 전국 2위, 국내 유일은 이번 문안에 쓰지 않았다. 증빙 전에는 낮은 수치나 익명 고객으로 바꾸어 대체하지도 않는다.

고객 사례를 이후 추가하려면 실제 작업·기간·서비스 범위·측정 원자료·분모와 분자·비교 조건·고객명/발언/이미지별 공개 동의가 필요하다. 노출을 방문으로, 방문을 매출로 바꾸지 않는다. 관찰된 변화만으로 인과관계를 단정하지 않는다.

B의 이미지에는 콘셉트 그래픽이며 고객 작업물이 아니라는 캡션이 있다. C의 편집 화면에는 콘텐츠 구성 예시라는 표시가 있다. 이 자료들을 실제 납품 포트폴리오로 소개하지 않는다.

## 구현 검토에서 전달한 수정 제안

아래는 처음 확인한 소스에 대한 제안이다. 구현 담당자에게 전달했으며, 반영 여부는 하단 재확인 기록에 적는다. 구두점과 어미 제안은 편집 선택이며 모든 원문을 맞춤법 오류라고 판단한 것은 아니다.

| 대상 | 확인한 내용 | 제안 및 이유 |
| --- | --- | --- |
| A 문의 서브카피 | “다음 이야기는, 원장님의 안경원입니다.” | “원장님의 안경원 이야기를 들려주세요.” 이야기와 안경원을 등치하는 어색함과 불필요한 쉼표 제거 |
| A 헤더 CTA | “상담하기”가 `mailto:` 연결 | “이메일로 상담” 선택 권장. 클릭 동작을 바로 알 수 있도록 함 |
| B 스크롤 본문 | “전문적인 설명을,” / “안경 제작 사례를 정리하고,” | 줄바꿈과 겹치는 불필요한 쉼표 삭제 권장 |
| B 홈페이지 서비스 | “안경원을 이해하는 한 곳” | “한곳에 담은 안경원 소개” 권장. 추상적인 장소보다 화면에 담는 내용을 명시 |
| B 서비스 CTA | “이 서비스 문의하기”가 `mailto:` 연결 | “이메일로 서비스 문의” 권장 |
| B 마지막 CTA | 본문은 합니다체, 초대 문구는 “이야기를 나눠요.” | “이야기를 들려주세요.” 권장. 독자의 다음 행동이 분명한 초대 문장 |
| C 상단 소문구 | “매장의 이야기에는, 다음 문장이 있습니다.” | 실제 업무 채널 표기로 대체 권장. 정보가 없는 추상 문장 줄임 |
| C 하단 CTA | “다음 문장은,” | 쉼표 삭제 권장 |
| C 문의 안내 | “보내주세요” | 브랜드 표기 통일을 위해 “보내 주세요” 권장. 원문을 명백한 오류라고 분류하지 않음 |
| C 채널 선택 | 플레이스·인스타그램을 선택해도 블로그의 ‘렌즈를 고른 이유/읽기 쉬운 글’ 문안 유지 | 선택에 맞는 예시 제목·설명도 변경 권장. 특히 플레이스는 매장 정보 관리라는 실제 업무와 맞춰야 함 |

C 플레이스 권장 문안은 “매장의 정보 / 찾아오는 길까지. / 안경원을 찾는 고객에게 필요한 정보를 정리합니다.”, 인스타그램은 “매장의 소식 / 새 소식을 한눈에. / 매장의 소식과 분위기를 사진과 글로 전합니다.”다. 이것은 예시 콘텐츠의 내용 변경이며 서비스 성과를 새로 주장하는 것이 아니다.

## 재확인 기록

- 1차 소스 검토 완료. 수정 제안을 root·B 개발 담당·C 개발 담당에게 전달했다.
- B의 수정 소스를 다시 읽었다. 불필요한 쉼표 2개 삭제, 홈페이지 서비스 표제 수정, 이메일 CTA 명시를 확인했다. 마지막 CTA는 모바일 줄폭을 고려한 “안경원 이야기를 / 들려주세요.”로 반영됐다.
- C의 수정 소스를 다시 읽었다. 상단 채널 표기, 하단 쉼표 삭제, “보내 주세요” 통일을 확인했다. `channelCopy`와 `setChannel()`이 채널별 표제·제목·본문을 교체하도록 변경되어 플레이스·인스타그램 선택의 의미가 명확해졌다.
- A의 두 항목은 root에게 선택적 윤문으로 전달했다. 실제 서비스나 성과를 오해시키는 허위 주장에 해당하지는 않는다.
- 통합 단계에서 A의 마지막 초대 문구를 “원장님의 안경원 이야기를 들려주세요.”로 반영했다.
- 구현 파일을 직접 수정하지 않았으며, 코드로 확인한 결과와 브라우저 검수 결과를 구분한다.
