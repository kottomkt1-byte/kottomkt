# 고객 사례와 주장 검증

검증 목적은 문장을 더 강하게 만드는 것이 아니라 독자가 오해하지 않도록 사실 범위를 정하는 것이다.

## 주장별 기록

수치·순위·독점성·고객 발언을 쓰려면 다음을 편집 기록에 남긴다. 민감한 원본을 Git에 복제하지 말고 접근 가능한 자료의 식별자만 기록한다.

| 필드 | 기록 내용 |
| --- | --- |
| 주장 | 공개하려는 정확한 문장과 적용 서비스 |
| 출처 | 원본 자료 위치·작성자·작성일, 확인한 사람 |
| 측정 범위 | 기간, 지역/채널, 대상 수, 산식·분모·분자 |
| 해석 | 관찰 결과인지 인과 효과인지, 비교 기준과 누락 조건 |
| 공개 권한 | 고객명·상호·로고·발언·사진별 동의 범위와 날짜 |
| 상태 | 사이트 표기만 확인 / 원자료 대조 완료 / 공개 동의 확인 / 보류 |

상태를 하나의 '검증 완료' 표시로 뭉뚱그리지 않는다. 진짜 자료라도 공개 동의가 없으면 고객 식별 사례로 게시하지 않는다.

## 사례 작성 기준

1. 실제 고객·작업 기간·제공 서비스가 확인되는지 확인한다. 테스트 예시를 실제 고객으로 바꾸지 않는다.
2. 노출, 클릭, 문의, 예약, 방문, 매출을 구별한다. 플레이스 노출 증가를 방문·매출 증가로 적지 않는다.
3. 전후 기간·광고비·시즌·매장 변화 등 비교 조건을 확인한다. 함께 변한 요인을 제외하지 않은 관찰만으로 '우리 서비스 덕분에'라고 단정하지 않는다.
4. 백분율 증가와 퍼센트포인트 증가를 구분한다. 분모가 0이거나 비교 기준이 불명확하면 증가율을 계산하지 않는다.
5. 직접 인용은 원문 그대로 둔다. 맞춤법을 고치거나 여러 문장을 합쳐 의미가 달라지면 인용으로 포장하지 않는다. 요약이면 '요약'임을 밝히고 원문 맥락을 유지한다.
6. 연락처, 프로필, 개인 이름, 고객 식별 정보를 점검한다. 공개 동의 없는 캡처나 로고는 쓰지 않는다. 개인정보를 가렸다는 사실과 '무편집'이라는 표현이 충돌하지 않게 한다.
7. 개별 사례의 결과를 보장·평균·전체 고객의 경험으로 확대하지 않는다. 별표 각주로 본문의 과장 주장을 정당화하지 않는다.

증빙이 없으면 해당 주장을 빼거나 서비스 업무 설명으로 대체한다. 숫자를 더 작은 숫자로 바꾸거나 익명 고객 A를 만들어 근거 문제를 숨기지 않는다. 확인 대기 항목은 고객에게 보이는 완성 카피와 분리해서 전달한다.

## 한국어 교정에서도 유지할 사실

날짜·숫자·단위·고유명사·부정·원인과 결과·직접 인용은 문체보다 우선한다. 원문 자체의 사실이 의심되면 조용히 수정하지 말고 근거 확인 대상으로 분리한다. '안경 제작 사례 작성 5,000건'을 '안경 제작 5,000건'으로 줄이지 않는다.
